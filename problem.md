# 1.2 Определение проблемы проекта

## Проблемы

Ключевые проблемы, которые призван решить проект. Проблемы 1 и 2 сформулированы как предположения: их нужно подтвердить в разговоре с врачами ДРКБ.

| № | Проблема | В чём она проявляется | Как решает «Ориентир» |
|---|---|---|---|
| 1 | Ручная сверка с возрастными нормами | У детей нормы зависят от возраста, пола, лаборатории и методики. При большом потоке анализов сверка вручную отнимает время и повышает риск пропустить отклонение | Врач вводит значения и интервалы из бланка, сервис автоматически отмечает показатели ниже, выше и в пределах интервала |
| 2 | Нужна быстрая справка и подсказка следующего шага | Врач не всегда помнит, что отражает редкий показатель и какой контроль или консультация для него обычно предусмотрены, а искать информацию долго | Справочные пояснения и рекомендации «для рассмотрения» по утверждённым правилам, оформленные ИИ |
| 3 | Использование ИИ с данными о здоровье детей | Сведения о здоровье — специальная категория персональных данных. Отправлять реальные данные во внешний ИИ-сервис небезопасно и юридически сложно | Анонимный ввод (только возраст, пол, название показателя и числа), данные нигде не сохраняются, ИИ получает только название показателя, направление отклонения и текст правила |
| 4 | Риск подмены решения врача и статус медицинского изделия | ИИ-рекомендация может быть воспринята как диагноз или назначение, а программа, интерпретирующая данные, может быть признана медицинским изделием | Рекомендации из утверждённых правил, а не из свободной генерации; пометка «для рассмотрения врачом»; строгие запреты для ИИ и проверка ответов; статус учебного прототипа до согласований |

## Ограничения проекта (что сервис НЕ делает)

- **Не ставит диагноз** и не формулирует диагностические гипотезы.
- **Не назначает лечение** и не называет лекарственные препараты.
- **Не даёт рекомендаций вне правил справочника.** Рекомендация (контроль, пересдача, консультация специалиста) выдаётся только если сработало утверждённое правило.
- **Не делает выводов по сочетанию показателей:** правила и пояснения составляются по одному показателю.
- **Не обрабатывает и не хранит персональные данные.** Нет полей для имён, номеров, дат и свободного текста, введённое не записывается.
- **Не принимает файлы и фото.**
- **Не заменяет врача:** все рекомендации даются для рассмотрения, решение принимает врач.
- **Не предназначен для клинического применения в статусе прототипа:** работает на синтетических данных и с учебными правилами.

## Цель проекта

Создать учебный прототип веб-приложения для врачей ДРКБ, которое сверяет детские лабораторные показатели с интервалами из бланка, даёт справочные пояснения и рекомендации для рассмотрения по утверждённым правилам с помощью ИИ, не обрабатывая персональные данные.

## Задачи проекта

1. Реализовать анонимный ввод: возраст (0–18 лет), пол, показатели, значения и референсные интервалы.
2. Реализовать автоматическую пометку отклонений.
3. Создать справочник показателей с пояснениями и правилами рекомендаций.
4. Реализовать модуль рекомендаций, который срабатывает по правилам в коде.
5. Подключить YandexGPT для оформления пояснений и рекомендаций с жёсткими запретами и проверкой ответа.
6. Обеспечить, чтобы введённые данные нигде не сохранялись.
7. Дать администратору инструменты ведения справочника, правил рекомендаций и правил для ИИ.
8. Обозначить статус учебного прототипа в интерфейсе и подготовить демонстрационные сценарии на синтетических данных.
9. Подготовить вопросы для больницы и юриста: статус медицинского изделия, допустимость внешнего ИИ-сервиса, источник и утверждение правил.
