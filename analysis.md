# Этап 1. Анализ

> Версия для согласования: проект «Ориентир», путь развития C (рекомендации врачу в учебном прототипе на синтетических данных).

## 1.1 Анализ предметной области

### Контекст

Врач-педиатр оценивает результаты лабораторных анализов ребёнка, сверяя каждое значение с референсным интервалом. У детей это сложнее, чем у взрослых: нормы зависят от возраста и пола, а у новорождённых и маленьких детей многие значения заметно отличаются от «взрослых». Кроме того, [референсные интервалы зависят от лаборатории, методики и прибора](https://www.msdmanuals.com/ru/professional/ресурсы/нормальные-лабораторные-показатели/референсные-интервалы-лабораторных-показателей), поэтому ориентироваться нужно на интервал, указанный в бланке.

Предполагается, что при большом потоке анализов ручная сверка отнимает время и повышает риск пропустить отклонение. Это предположение нужно подтвердить с ДРКБ.

Задание проекта: «Применение ИИ в обработке медицинских данных». Данные о здоровье детей очень чувствительны, поэтому ИИ-сервис должен работать без обработки персональных данных.

### Статус проекта: учебный прототип

«Ориентир» разрабатывается как **учебный прототип**. Он работает на вымышленных (синтетических) данных и не внедряется в клиническую практику, пока не пройдены шаги из раздела «Нормативные рамки». Рекомендации в прототипе включены, но помечены в интерфейсе как учебные и не предназначенные для клинического применения.

### Решение

**Ориентир** — веб-приложение-помощник врача ДРКБ. Врач вводит:
- возраст ребёнка (в годах и месяцах) и пол;
- название показателя, значение и референсный интервал из бланка.

Сервис:
1. Проверяет ввод: допустимы только числа и значения из списков, свободного текста нет.
2. Сравнивает значения с интервалами, отмечает «ниже», «в пределах» или «выше» и показывает величину отклонения.
3. Показывает справочное пояснение к каждому отклонённому показателю.
4. Формирует **рекомендации врачу для рассмотрения**: контроль или пересдача анализа и консультация специалиста профильного направления. Окончательное решение принимает врач.

**Как формируются рекомендации.** Чтобы рекомендации были проверяемыми и не зависели от «памяти» языковой модели, предлагаются четыре правила:
1. Рекомендации берутся из **правил справочника**. В прототипе это учебные правила, в реальной эксплуатации их должен писать и утверждать медицинский эксперт ДРКБ по клиническим рекомендациям.
2. Правила срабатывают **в коде**, а не в модели. Возраст и пол используются локально для выбора правила и никуда не отправляются.
3. Правила составляются **по одному показателю**. Выводы по сочетанию показателей в прототип не входят: они ближе всего к диагностике.
4. YandexGPT только **оформляет текст**: получает название показателя, направление отклонения и текст правила, не добавляет новых фактов. Если ответ нарушает запреты или модель недоступна, показывается текст правила без ИИ.

**Что сервис не делает:** не ставит диагноз, не назначает лечение и не называет препараты, не делает выводов по сочетанию показателей, ничего не хранит, не принимает файлы и фото. Подробнее в `problem.md`.

**Роль ИИ.** Числа и правила обрабатывает код, это надёжнее и легче проверить. ИИ работает как языковой слой: оформляет пояснения и рекомендации, помогает сопоставить введённое название показателя с записью справочника («Hb», «HGB», «Гемоглобин»), может переписать справку простым языком, чтобы врач объяснил её семье. Это осознанный выбор безопасной архитектуры: основная ответственность за медицинское содержание лежит на утверждённых правилах, а не на модели.

### Участники

| Участник | Что ему нужно |
|---|---|
| Врач ДРКБ | Быстро увидеть отклонения, получить справку и рекомендации для рассмотрения, не вводя данных, идентифицирующих ребёнка |
| Администратор (команда проекта) | Вести справочник показателей, правила рекомендаций и правила для ИИ |
| Медицинский эксперт ДРКБ | Утверждать пояснения и правила рекомендаций. В прототипе используются учебные правила, при внедрении роль обязательна |

### Нормативные рамки

**Персональные данные.** Сведения о состоянии здоровья относятся к [специальной категории персональных данных](https://www.purrweb.com/ru/blog/personalnye-dannye-pacienta-v-medicine/). Обезличенные данные [выходят из-под действия закона о персональных данных, только если по ним практически невозможно определить человека](https://habr.com/ru/articles/931348/). Убрать только имя недостаточно: возраст, пол, редкий диагноз, точные даты и регион вместе могут выдать ребёнка. С 1 сентября 2025 года действует [приказ Роскомнадзора №140 с требованиями к обезличиванию](https://ppt.ru/amp/obzory/vstupaet-v-silu/prikaz-roskomnadzora-19-06-2025-140) (ссылка на пересказ приказа, полный текст не изучался). Поэтому в проекте нет полей для идентификаторов и дат, нет свободного текста, а введённые данные не сохраняются.

**Медицинское изделие.** Критерии отнесения программ к медицинским изделиям [не закреплены законом](https://brace-lf.com/ru/informaciya/farmatsevticheskoe-i-meditsinskoe-pravo/programmnoe-obespechenie-meditsinskoe-izdelie-kriterii-registratsii). По письму Росздравнадзора от 13.02.2020 № 02И-297/20 (в изложении юридической статьи, текст письма не изучался) программа считается медицинским изделием, если она предназначена для оказания медпомощи и интерпретирует данные автоматически, в том числе с помощью ИИ, влияя на клинические решения. В той же статье программами такого рода названы системы поддержки врачебных решений (при инсульте, оценка риска рака). Решение врача при этом не снимает вопрос: значение имеет назначение программы и влияние на решения. Не относятся к интерпретации расчёты, графики, перевод единиц и сигнализация отклонений. Справочные программы для неограниченного круга пользователей регистрации не требуют. Распространение незарегистрированного медицинского изделия, по [материалу «Фармвестника»](https://pharmvestnik.ru/articles/Doktor-PO.html), может грозить серьёзной ответственностью, а граница размыта даже для разработчиков.

Рекомендации о пересдаче и специалисте относятся к зоне риска. Поэтому проект делится на два этапа:

| Этап | Данные | Рекомендации | Что нужно |
|---|---|---|---|
| Учебный прототип (до 1 декабря) | Вымышленные, синтетические | Включены, помечены как учебные | Подтвердить у руководителя задания, что такой формат допустим. Предположение: до внедрения в больнице вопрос регистрации не встаёт, но это нужно проверить |
| Внедрение в больнице | Введённые врачом обезличенные показатели | Только после согласований | Заключение о статусе медицинского изделия, согласие больницы на внешний ИИ-сервис, правила рекомендаций, утверждённые медицинским экспертом |

Это мой разбор открытых источников, а не юридическое заключение. Окончательное решение должны принять больница и юрист.

**Выводы:**
- В изученных описаниях не нашёлся инструмент для педиатров, который сверяет детские значения с интервалами из бланка, даёт рекомендации врачу, работает без персональных данных и ничего не хранит.
- Подсказки о том, к какому специалисту обратиться, есть у сервисов для пациентов (Vrach.info). Они работают с загруженными бланками, то есть с данными, содержащими персональные сведения.
- Отличие «Ориентира»: рабочий инструмент врача, анонимный ввод, отсутствие хранения, рекомендации по утверждённым правилам вместо свободной генерации моделью и жёсткие ограничения на ИИ.

### Основные понятия

| Понятие | Значение |
|---|---|
| Референсный интервал | Нижняя и верхняя границы нормы, указанные в бланке лаборатории; зависят от возраста, пола, методики |
| Отклонение | Значение ниже нижней или выше верхней границы интервала |
| Справочник показателей | Список показателей с единицами измерения, утверждёнными справочными пояснениями и правилами рекомендаций |
| Справочное пояснение | Короткий общий текст о том, что отражает показатель; не относится к конкретному ребёнку |
| Правило рекомендации | Условие вида «показатель ниже интервала → рассмотреть контроль или консультацию специалиста профильного направления»; составляется по одному показателю |
| Рекомендация для рассмотрения | Текст по сработавшему правилу, который врач может принять или отвергнуть |
| Правила для ИИ | Список запретов и требований к тексту, который формирует YandexGPT |
| Учебный прототип | Режим работы на синтетических данных с пометкой «не для клинического применения» |
